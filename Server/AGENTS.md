# Правила работы с модулем Server

## Контекст и границы

`Server/` — тестовый backend личного кабинета, из которого запускается игра.
Статический фронт кабинета находится в `../Client` и раздаётся этим сервером.
Контракт API описан в `README.md`; при его изменении обновите README, тесты и
`../Client/app.js`.

Сервер не знает внутреннего состояния игры. Приём результатов рейса из игры
добавляется только вместе с реальной отправкой из `Game/`.

## Среда и команды

- Node.js ≥ 22.18.0, рекомендуемая версия в `.nvmrc`.
- TypeScript исполняется напрямую (type stripping): только стираемый синтаксис
  (`erasableSyntaxOnly`), без `enum`, `namespace` и parameter properties;
  относительные импорты с расширением `.ts`.
- Хранилище — `node:sqlite`, внешних драйверов нет.
- Swagger UI: `/api/docs`, спецификация: `/api/openapi.json`.

Из каталога `Server/`:

```powershell
npm ci --include=dev
npm run dev
npm run verify
```

## Правила

- Каждый маршрут объявляется через `createRoute` из `@hono/zod-openapi`, схемы —
  в `src/schemas.ts`. Ответы из БД проходят `Schema.parse`, чтобы контракт и
  OpenAPI не расходились с фактическими данными. Маршрут без `createRoute` не
  попадёт в Swagger.
- `createApp` получает БД, конфиг и часы явно — тесты работают на `:memory:`
  через `app.request()` без поднятия порта.
- Не возвращайте хеши паролей и токенов в ответах.
- Файл БД (`data/`) не коммитится.
