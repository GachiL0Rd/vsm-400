# Данные и доступ

Речь о составе базы и о том, как API её закрывает. Юридическую квалификацию
оператора, приказ об обработке и аттестацию контура заказчик в материалах
хакатона не фиксировал. Ниже только то, что делает Backend.

Опора: SPEC §3, §6, §10, модель `prisma/schema.prisma`, концепт (блок
«Данные и 152-ФЗ»): ник вместо ФИО, табельный номер только как HMAC,
демо-люди синтетические.

## Что хранится

Учётка `User`:

- `login`;
- `passwordHash` — argon2id, не пароль;
- `callsign` — 4 символа, уникальный позывной (`A7F3`), не фамилия;
- `extHash` — HMAC-SHA256 табельного номера с перцем `EXT_ID_PEPPER`, или
  пусто, если человека завёл не HR;
- роль, грейд, должность, бригада, флаги пароля и блокировки.

Табельный номер и ФИО колонками не являются. Обратный проход от `extHash` к
номеру без перца не устроен: перец только в env.

Рядом, уже не паспорт:

- оргструктура депо и бригад (код, название, город депо);
- сессии входа: хеш refresh, user-agent, IP, сроки, отзыв;
- игровые сессии, журнал `GameEvent`, рейсы, решения, шкалы, компетенции;
- леджер очков, ачивки, сезон, уведомления, рекомендации к грейду;
- клиенты интеграции: sha256 ключа `vsm_<id>_<secret>`, scopes, URL вебхука;
- `AuditLog`: тип актёра, id, действие, цель, meta, IP, время.

`seedEnc` — seed смены под AES-256-GCM. Это не персональные данные, ключ
`SEED_ENC_KEY` в базе не лежит. `seedCommit` — открытый SHA-256, по нему seed
не восстанавливается.

Тексты решений (`situation`, `action`) — строки сценария, который прошли.
Паспорт пассажира и ФИО из игрового `DialogueView` в модель Backend не
записываются. Контракт v1 может показать их в кадре симуляции как реквизит
сцены. В учётке сотрудника их нет.

## Чего нет в базе

- ФИО, телефона, почты сотрудника;
- сырого табельного номера;
- пароля, refresh-токена, API-ключа, игрового билета целиком (у билета в
  Redis только отметка погашенного `jti`);
- seed в открытом виде;
- медицинских и платёжных данных. Сценарий про недомогание хранит выбор
  проводника, не карту здоровья.

В логах и в seed нет ФИО. Bootstrap печатает пароль администратора один раз.
Структурный лог не пишет пароль, cookie и `X-Service-Token`.

Пассажиры сценариев — вымышленные роли. Концепт прямо запрещает имена и фото
реальных людей. Имена вроде тех, что стоят в dev-стенде игры, в сид Backend
не переносятся как сотрудники.

## Синтетический seed

`prisma db seed` заводит стенд, не контур заказчика: два условных депо,
бригады, позывные, демо-логины `demo`, `chief`, `methodist`. История рейсов
считается движком, не ручными «реальными» сменами. Повторный seed на базе, где
уже есть люди HR, политикой SPEC не описан и на проде не запускается
(`migrate deploy` его не вызывает).

Пароль демо из `.env` / сида — только своя машина. В закрытый контур файл
`.env.example` не подставляется.

## Роли

| Роль | Что видит |
| --- | --- |
| `CONDUCTOR` | Свой `/me`, свои рейсы и разбор, сравнение себя со средним бригады и депо, ленту, рейтинг по позывным. |
| `CHIEF` | Плюс теплокарта и пробелы своей бригады, назначение сценария, решение по рекомендации к грейду. |
| `METHODIST` | Аналитика бригад, версии сценариев, назначения. |
| `ADMIN` | Учётки. Первый админ появляется bootstrap'ом, не формой регистрации. |

Чужой разбор рейса проводнику не отдаётся. Рейтинг показывает позывной,
очки сезона и место, не `extHash` и не логин. Аналитика по людям бригады —
у бригадира и методиста, как в концепте. Грейд система только рекомендует.
`PromotionRecommendation` проводит CHIEF или HR, самоповышения нет.

HR — не роль пользователя и не cookie. Запись `ApiClient`, заголовок
`X-API-Key`. Ключ в базе — sha256. Ручки: upsert сотрудника по внешнему id
(в ответе одноразовый пароль, в базе `extHash`), прогресс, оргструктура,
подписка на вебхук. Тело прогресса — позывной, уровень, шкалы, не ФИО.

Вебхук подписывается HMAC-SHA256 в `X-VSM-Signature`. Секрет подписки хранится
на записи `WebhookSubscription`. Чужой URL без подписи не считается доставкой.

## Аудит

`AuditLog.actorType`: `USER`, `API_CLIENT`, `SYSTEM`, `GAME_SERVER`.
Пишутся вход, отказ входа, смена пароля, отзыв refresh при повторном
использовании, погашение и повтор билета, подозрительный рейс, решение по
грейду, вызовы интеграции. В `meta` не кладут пароль, билет и сырой табельный.

Подозрительный рейс (`Run.suspicious`) остаётся в истории. В рейтинг его очки
не попадают, пока флаг не снят. См. `anti-cheat.md`.

## Секреты

Только env. Список и минимумы длины — `src/config/env.ts` и `.env.example`.
`.env` в git не входит. Образ его не копирует.

| Переменная | Зачем |
| --- | --- |
| `JWT_ACCESS_SECRET` | Подпись access-JWT. |
| `GAME_TICKET_SECRET` | Подпись билета `aud=vsm-game`. |
| `GAME_SERVER_TOKEN` | Заголовок `X-Service-Token`. |
| `SEED_ENC_KEY` | AES-256-GCM для seed смены. |
| `EXT_ID_PEPPER` | HMAC табельного номера. |

Утечка `EXT_ID_PEPPER` позволяет перебирать табельные номера в HMAC.
Утечка `GAME_SERVER_TOKEN` позволяет сдать `RunReport`. Оба меняются сменой
env и рестартом. Отдельного KMS в постановке нет.

## Cookie

| Cookie | Срок | Флаги |
| --- | --- | --- |
| `vsm_access` | 15 минут | HttpOnly, SameSite=Lax, Path=/, Secure в prod. JWT. |
| `vsm_refresh` | 7 дней | HttpOnly, SameSite=Strict, Path=/api/v1/auth. Opaque, в базе хеш. Ротация каждый refresh. |
| `vsm_game` | 2 минуты | HttpOnly, SameSite=Strict, Path=/game, Secure в prod. Билет. |

`SameSite=None` не используется. Токен кабинета в `localStorage` не кладётся.
Secure включает `COOKIE_SECURE=true` (в проде за TLS — да). Схема env не
подставляет `true` сама только из `NODE_ENV=production`: флаг явный, чтобы
локальный профиль `app` по HTTP мог подняться.

Path=`/game` не покрывает URL `/game-ws`. Для сокета билет дублируется в
`hello.ticket`. Подробности — `game-server-contract.md`.

## CORS и заголовки

`enableCors`: origin только из `CORS_ORIGINS` (список через запятую),
`credentials: true`. Методы: GET, POST, PUT, PATCH, DELETE, OPTIONS.
Заголовки запроса: `Content-Type`, `Authorization`, `X-API-Key`,
`X-Service-Token`.

Helmet (`@fastify/helmet`) включён в `configure-app.ts`. CSP выключен:
Swagger UI ставит inline-скрипты, остальные заголовки helmet остаются.
При дефолтах helmet 8 это, среди прочего:

- `Strict-Transport-Security: max-age=31536000; includeSubDomains`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: no-referrer`
- `Cross-Origin-Opener-Policy: same-origin`
- `Cross-Origin-Resource-Policy: same-origin`
- `Origin-Agent-Cluster: ?1`
- `X-XSS-Protection: 0`
- снятие `X-Powered-By`

HSTS на локальном HTTP без TLS браузер всё равно получит, если ходит на
этот порт. В контуре TLS терминирует прокси. Заголовок дублировать на Caddy
имеет смысл; выключать его на Backend SPEC не просит.

Тело запроса обрезается на 1 МиБ (`BODY_LIMIT_BYTES` в `src/main.ts`).
Ошибки — `application/problem+json`: `type`, `title`, `status`, `detail`,
`code`, у zod ещё `errors[]`. Текст исключения в 500 не отдаётся.
Неверный логин не сообщает, чего не хватило, логина или пароля.
