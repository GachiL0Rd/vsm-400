# Участие в разработке

## Ветки

- `main` — основная интеграционная ветка разработки; она должна оставаться
  запускаемой и проходить проверки.
- `release` — отобранные стабильные снимки для выпуска и демонстрации.
- `feature/<name>` — новая функциональность от `main`.
- `fix/<name>` — исправление от `main`.
- `docs/<name>` и `chore/<name>` — документация и инфраструктура.

Обычная работа начинается от актуальной `main` и возвращается в неё через
небольшой обозримый pull request. Ветка `dev` является исторической и для новой
работы не используется. Перенос проверенного `main` в `release` выполняется в
точке, где приложение устанавливается с нуля, проходит проверки, собирается и
запускается.

## Перед pull request

Выполните локальные команды установки и проверки каждого затронутого модуля.
Они описаны в его `README.md` и `AGENTS.md`. Для визуальных изменений также
запустите модуль и проверьте изменённый сценарий вручную.

Pull request должен объяснять:

- что изменилось;
- как это проверено;
- какие известные ограничения остались;
- затрагивает ли изменение контракт между будущими модулями.

Обычные pull request направляются в `main`. Перенос в `release` оформляется
отдельно и допускается только после полного набора release-проверок из
[`docs/agent/workflow.md`](docs/agent/workflow.md).

Не смешивайте независимые изменения в одной ветке. Не коммитьте generated
output, локальные настройки редактора, секреты и зависимости из
`node_modules/`.

## Инструменты

Для участия достаточно Git, Node.js и npm. Дополнительные инструменты, удобные
агентам и желающим участникам, перечислены в
[`docs/agent/tools.md`](docs/agent/tools.md).
