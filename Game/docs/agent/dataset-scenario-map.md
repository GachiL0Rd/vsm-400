# Карта ситуаций Dataset для клиента

Источник: `E:/hackatonmoscoww/Dataset/Ситуации на борту.pdf`, страницы 3–19.
Каждая строка ниже относится к номеру ситуации на указанной странице PDF.
Текст PDF описывает общение и действия персонала; это не исполняемые правила
сервера. В таблице указан **клиентский способ показа и ввода**, без выдуманной
нормативной команды или автоматической оценки.

Обозначения: **Д** — воспроизводимый dev-стенд; **К** — общий контракт/UI
поддерживает тип взаимодействия, конкретный контент и серверное правило пока
не созданы. `Dialogue` — максимум три ответа и два уровня; `Task` — отдельная
сущность со сроком; `observe` — видимый признак; `inspect` — осмотр;
`report` — семантический доклад. Все последствия подтверждает сервер.

## Категории и демонстрация

| Категория | Действующий стенд | Остальное покрытие |
| --- | --- | --- |
| Запрос услуги/обслуживания | №27: Dialogue + отдельный Task, срок, результат | `TaskView`, контекстные команды, наблюдаемая реакция |
| Жалоба на неисправность | Техническая проба давления: жалоба NPC, быстрый/полный осмотр, доклад | `CueView`, `PoiView.observation`, `inspect`, `report` |
| Конфликт | №23: уточнение и сверка билетов меняют ответ/результат | те же Dialogue/Task для №10, 13, 25, 33, 37 |
| Проверка документа | Экран билета и удостоверения для тестового пассажира | `DialogueView.document/ticket`, подтверждаемое решение |
| Опасность/срочная реакция | Пожар: дым, огонь, предмет, альтернативные исходы | `CueView`, срочный Task и команды для других опасностей |
| Общение/объяснение | Базовые реплики и варианты ответа | сервер поставляет содержание и последствия для остальных номеров |

Три файла стандартов в Dataset служат источником для будущего серверного
контента: общий сервис (`974_р`), помощь маломобильным пассажирам (`989_р`),
оснащение вагона (`990_р`). Они не создают новых скрытых полей на клиенте.
Фотографии Dataset использовались только как ориентир планировки, не как
готовые игровые ассеты. Тестовая графика создана отдельно.
