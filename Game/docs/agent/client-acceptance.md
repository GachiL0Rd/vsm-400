# Приёмка клиентского игрового слайса

Дата: 25.09.2026. Ветка: `feature/mechanics-playground`.

## Что реализовано

| Требование цели | Проверяемый результат |
| --- | --- |
| Граница клиента и сервера | `src/client/protocol.ts`, `state.ts`, `connection.ts`: публичный snapshot, упорядоченные дельты, семантические команды, ack/reject, повторная синхронизация и переподключение. Незнакомые скрытые поля отбрасываются при разборе. Повторный клик не отправляет команду второй раз до результата. |
| Изометрический мир | `src/client/map.ts`, `scene.ts`, `public/sprites/`: перрон, вагон, двери, кресла, панель, сервисная зона, туалет, огнетушитель, проводник и четыре разных пассажира. Кресла и стены ограничивают маршрут; сидящие NPC находятся на креслах, подход к ним остаётся свободным. |
| Наблюдения и действия | `src/client/ui.ts`: выбор объекта и пассажира, подход, быстрый/подробный осмотр, сравнение документа с билетом, диалог до двух уровней, отдельные запросы со сроками, предмет и его состояния, свист/дым/огонь, независимые показатели и объясняющий итог. Видимые события сопровождаются текстом; есть звук с регулятором громкости. |
| Сценарии | `dev/demo-server.ts`: давление, пожар, сервисная просьба №27 и конфликт №23. Каталог всех 51 ситуации и границы стенда — `docs/agent/dataset-scenario-map.md`. |
| Интеграция коллеги | Сообщения, валидация, порядок, ошибки, настройки endpoint и сценарии описаны в `docs/agent/game-websocket-contract.md`; адрес задаётся метатегом или `VITE_GAME_WS_URL`. |
| Production | `npm run build` включает клиент без dev-сервера и прежних скрытых расчётов; `scripts/check-bundle.mjs` проверяет их отсутствие в JS-бандле. |

## Проверка

Из `Game/` выполнены `npm ci --include=dev` и `npm run verify`: Biome, TypeScript, 28 тестов в 10 файлах, production-сборка и проверка бандла прошли. Biome оставляет 11 предупреждений о сложности функций и старых `!` в тестах; ошибок нет. Vite предупреждает о размере чанка Phaser (1,4 МБ), сборка успешна.

В реальном Chromium выполнены `node scripts/browser-smoke.mjs` и `node scripts/browser-flow.mjs` через локальный WebSocket стенд. Проверены экран 1440×900 и узкий 430×850, ввод, смена зон и состояния предмета; необработанных ошибок в консоли нет. Полный маршрут включает сопоставление документа и билета, жалобу на давление, уточнение, оба осмотра, доклад и итог. Отдельно пройдены тушение пожара, бездействие при пожаре, сервисный запрос, конфликт, восстановление после разрыва и очистка диалога/Task при перезапуске.

Наблюдаемые итоги стенда: давление 89/87, успешное тушение 91/90, пожар без реакции 35/58, сервис 100/95, конфликт 100/94 (безопасность/сервис). Скриншоты лежат в локальной игнорируемой папке `artifacts/`: `start-1440.png`, `start-430.png`, `document-comparison.png`, `pressure-selected.png`, `pressure-success.png`, `fire-success.png`, `fire-failure.png`, `service-success.png`, `conflict-success.png`, `narrow-interaction.png`. Сгенерированные файлы в коммиты не входят.

## Допущения и следующая интеграция

Локальный стенд фиксирует четыре коротких сценария и демонстрирует клиентский протокол; он не заменяет серверную модель NPC, скрытой сетки и оценивания. Реальный WebSocket endpoint коллеги ещё предстоит подключить по документированному контракту. Остальные ситуации Dataset распределены по общим типам взаимодействий и не превращены в 51 отдельный сценарий. Тестовые оригинальные спрайты можно заменить финальным артом без изменения протокола.
