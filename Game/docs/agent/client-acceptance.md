# Приёмка клиентского игрового слайса

Дата обновления: 26.09.2026. Ветка: `feature/mechanics-playground`.

## Что реализовано

| Требование цели | Проверяемый результат |
| --- | --- |
| Граница клиента и сервера | `src/client/protocol.ts`, `state.ts`, `connection.ts`: публичный snapshot, упорядоченные дельты, семантические команды, ack/reject, повторная синхронизация и переподключение. Незнакомые скрытые поля отбрасываются при разборе. Повторный клик не отправляет команду второй раз до результата. |
| Top-down мир и управление | `src/client/GameScene.ts`, `map.ts`, `managers/WorldManager.ts`, `PlayerManager.ts`, `NpcManager.ts`, `PoiManager.ts`, `InputManager.ts`, `CollisionManager.ts`: перрон, вагон, проход, двери, кресла, панель, сервисная зона, туалет, огнетушитель, проводник и четыре различимых пассажира. Мир составлен из простых фигур и надписей; путь обходит занятые NPC клетки. |
| Наблюдения и действия | `src/client/managers/{Interaction,Hud,Dialogue,Sound,Vfx,Pause}Manager.ts`: выбор объекта и пассажира, подход, два вида осмотра, сравнение документа с билетом, диалог до двух уровней, запросы со сроками, состояния предмета, свист/дым/огонь, показатели и объясняющий итог. Видимые события сопровождаются текстом; есть звук с регулятором громкости. |
| Жизненный цикл клиента | Одна `GameScene` собирает менеджеры; `GameConnection` остаётся сетевым компонентом. Владение объектами, callbacks и очистка описаны в `docs/agent/game-client-architecture.md`. |
| Сценарии | `dev/demo-server.ts`: давление, пожар, сервисная просьба №27 и конфликт №23. Каталог всех 51 ситуации и границы стенда — `docs/agent/dataset-scenario-map.md`. |
| Интеграция коллеги | Сообщения, валидация, порядок, ошибки, настройки endpoint и сценарии описаны в `docs/agent/game-websocket-contract.md`; адрес задаётся метатегом или `VITE_GAME_WS_URL`. |
| Production | `npm run build` включает клиент без dev-сервера и прежних скрытых расчётов; `scripts/check-bundle.mjs` проверяет их отсутствие в JS-бандле. |

## Проверка

Из `Game/` выполнены `npm ci --include=dev` и `npm run verify`: Biome, TypeScript, 30 тестов в 11 файлах, production-сборка и проверка бандла прошли. Предупреждения Biome не блокируют проверку. Vite предупреждает о размере чанка Phaser (1,4 МБ), сборка успешна.

В реальном Chromium выполнены `node scripts/browser-smoke.mjs`, `node scripts/browser-flow.mjs` и `node scripts/browser-lifecycle.mjs` через локальный WebSocket стенд. Проверены экран 1440×900 и узкий 430×850, мышь и касание, смена зон, отказ команды, пауза, состояния предмета, два перезапуска сцены и очистка при `game.destroy()`; необработанных ошибок в консоли нет. Полный маршрут включает сопоставление документа и билета, жалобу на давление, уточнение, оба осмотра, доклад и итог. Отдельно пройдены тушение пожара, бездействие при пожаре, сервисный запрос, конфликт, восстановление после разрыва, отсутствие повторного звука/VFX на полном snapshot и очистка диалога/Task при новом сеансе.

Наблюдаемые итоги стенда: давление 89/87, успешное тушение 91/90, пожар без реакции 35/58, сервис 100/95, конфликт 100/94 (безопасность/сервис). Скриншоты лежат в локальной игнорируемой папке `artifacts/`: `start-1440.png`, `start-430.png`, `document-comparison.png`, `pressure-selected.png`, `pressure-success.png`, `fire-success.png`, `fire-failure.png`, `service-success.png`, `conflict-success.png`, `narrow-interaction.png`. Сгенерированные файлы в коммиты не входят.

## Допущения и следующая интеграция

Локальный стенд фиксирует четыре коротких сценария и демонстрирует клиентский протокол; он не заменяет серверную модель NPC, скрытой сетки и оценивания. Реальный WebSocket endpoint коллеги ещё предстоит подключить по документированному контракту. Остальные ситуации Dataset распределены по общим типам взаимодействий и не превращены в 51 отдельный сценарий. Текущие плейсхолдеры можно заменить финальным артом без изменения протокола.
