# Требования к ассетам текущего demo

**Версия документа:** 0.2.0  
**Статус:** Draft / artist handoff  
**Дата редакции:** 2026-09-27

## 1. Общий принцип

Для интерактивных референсов нужен не только отдельный элемент вагона, но и приближённое close-up представление, пригодное для модального взаимодействия.

Динамически меняющиеся части желательно отдавать отдельными прозрачными слоями.

Client должен иметь возможность собирать состояние объекта программно без хранения отдельной полной картинки для каждой комбинации.

## 2. Огнетушитель

Нужны:

1. вариант огнетушителя на стене;
2. close-up/modal base;
3. переносимый/held вариант;
4. по возможности отдельный нейтральный фон/крепление.

Отдельные слои:

- чека/пломба — снимаемая;
- стрелка манометра — отдельно от шкалы;
- повреждение корпуса (`scratch/scar/dent`) — overlay;
- при необходимости отдельные элементы маркировки.

Манометр можно рисовать со шкалой/индикаторной зоной, но без встроенной стрелки.

Фон желательно отделить от корпуса, чтобы один close-up можно было использовать как для настенного, так и для held состояния.

## 3. Климат-контроль

Нужна упрощённая базовая панель:

- пустой дисплей;
- две визуальные секции;
- рамка/ободок;
- минимум лишних элементов.

Отдельно подобрать:

- читаемый цифровой шрифт;
- иконку температуры;
- иконку/кнопку проверки связи;
- иконку давления;
- иконку дыма/датчика дыма.

Числа и статусы рисуются программно.

## 4. Стоп-кран

Нужно close-up представление.

Отдельные слои:

- основание/слот;
- ручка;
- пломба.

Пломба должна быть визуально доступной и легко читаемой.

Ручка должна быть отделена от основания, чтобы Client мог переключать положение без замены всей картинки.

## 5. Билет

От художника нужна визуальная основа/обложка билета.

Все значимые значения вставляются программно.

Нужно подобрать шрифт, пригодный для:

- ФИО;
- номера поезда;
- даты/времени;
- вагона/места;
- документа;
- дополнительных коротких подписей.

QR/код может быть отдельным placeholder или генерируемым элементом.

## 6. Паспорт

Нужен раскрытый документ.

Отдельные зоны:

- фотография;
- ФИО;
- дата рождения;
- номер документа.

Содержимое вставляется программно.

## 7. Журнал приёмки

Нужен раскрытый журнал/книга с достаточно чистой рабочей областью для динамического checklist.

Дополнительно нужен переносимый вариант:

- как предмет в руках персонажа;
- либо как выразительная inventory/held icon, если это будет выбранный UI style.

## 8. Связь с машинистом

Нужен узнаваемый элемент связи как часть интерьера вагона.

Сложный close-up не обязателен для первой версии. При необходимости достаточно простого состояния/индикатора связи.

## 9. Персонажи

Нужны совместимые:

- базовые манекены;
- слои одежды;
- при необходимости аксессуары;
- held representation журнала и огнетушителя.

Конкретный формат слоёв и naming convention будут зафиксированы после первого art integration spike.

## 10. Требования к передаче ассетов

До утверждения pipeline желательно сохранять:

- прозрачность для overlay layers;
- одинаковый canvas/anchor у частей одного close-up;
- логические имена слоёв;
- отсутствие запечённого текста там, где он должен меняться программно;
- отсутствие запечённого состояния там, где оно должно управляться simulation state.


## Еда и напитки baseline

На текущем этапе отдельные художественные ассеты еды, напитков, посуды и мусора не обязательны. Service point может использовать простой UI, а held food/drink — временную иконку или условное обозначение.

Это сознательное ограничение baseline и не должно блокировать service gameplay.
