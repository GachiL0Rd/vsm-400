# План рейса и окна обслуживания

**Версия документа:** 0.2.0  
**Статус:** Draft / concrete demo implementation  
**Дата редакции:** 2026-09-27

## 1. Назначение

Этот документ фиксирует примерный ритм короткого demo-рейса и способ представить его в Scenario.

Точные часы являются параметрами конкретного сценария. Общая архитектура не предполагает, что питание или подготовка к прибытию всегда происходят в одно и то же время.

## 2. Разделение приёмки и посадки

`preDeparture` остаётся отдельной предрейсовой приёмкой без пассажирского потока.

После неё Scenario может содержать исходную остановку (`originStop`) с посадкой пассажиров до фактического отправления.

```text
preDeparture
  осмотр вагона
  журнал приёмки
  пассажиров нет
        ↓
originStop
  посадка
  документы
  размещение
        ↓
departure
        ↓
travel / stops / service windows
```

Это позволяет одновременно сохранить отдельную приёмку и реалистичную посадку до отправления.

## 3. Примерный план demo-рейса

| Время | Событие | Основание / статус |
|---|---|---|
| 11:30–11:55 | Посадка, проверка документов, размещение пассажиров | нормативная функция проводника; конкретное начало за 30 минут — условие сценария |
| 11:55–12:00 | Завершение посадки, готовность вагона | время условное |
| **12:00** | Отправление | расписание сценария/поезда |
| 12:00–12:10 | Помощь пассажирам после отправления, размещение ручной клади | обязанность проводника; интервал сценарный |
| **12:15–12:45** | Питание пассажиров классов, где оно включено | расписание перевозчика/сценария; общего фиксированного норматива по времени не предполагается |
| 12:45–13:00 | Постсервисное окно / текущее обслуживание | в baseline сбор посуды и мусора не моделируется |
| 13:00–14:00 | Текущее обслуживание пассажиров; контроль порядка и климата | действует весь рейс; интервал здесь выбран для demo |
| 14:05 | Подготовка к прибытию, информирование пассажиров | своевременное уведомление; «за 15 минут» — сценарное расписание |
| **14:20** | Прибытие и безопасная высадка | маршрутное расписание |

При необходимости между этими окнами Scenario может содержать промежуточные остановки. Таблица описывает сервисный ритм, а не запрещает route stops.

## 4. Service windows

Не требуется превращать каждую строку таблицы в отдельный Stage.

Scenario может содержать набор временных окон обслуживания:

```ts
interface ServiceWindowDefinition {
  id: string;
  start: ScenarioTimeAnchor;
  end?: ScenarioTimeAnchor;
  passengerSelector?: SelectorExpression;
  services?: string[];
  expectations?: string[];
}
```

Примеры:

```text
post-departure-assistance
meal-service
post-meal-service
ongoing-service
arrival-preparation
```

Окно является контекстом для candidate actions, assessment и coaching, но не собственной state machine.

## 5. Time anchors

Для baseline достаточно относительных anchors:

```text
after departure
before final arrival
on origin boarding begin/end
on stop enter/leave
```

Конкретный сценарий может дополнительно хранить display clock (`12:00`, `14:20`) для UI.

Simulation всё равно работает по своей `SimTimeUs` шкале.

## 6. Питание

Окно питания повышает уместность service actions и запросов, но не является hard filter. Класс пассажира определяется trait (`basic`, `comfort`, `business`).

Пассажир другого класса всё ещё может запросить питание. Такой запрос выражается обычным waiting action и оценивается с учётом entitlement его class trait.

## 7. Текущее обслуживание

`ongoing-service` не означает, что NPC обязаны непрерывно генерировать запросы.

Окно лишь задаёт контекст:

- какие service actions уместны;
- какие запросы имеют повышенные logits;
- какие response expectations действуют;
- какие coaching hints доступны.

## 8. Подготовка к прибытию

Предприбытие удобнее задавать относительным событием:

```text
finalArrival - 15 min
```

чем отдельным жёстким Stage.

При наступлении окна могут становиться актуальными действия:

- информирование пассажиров;
- проверка порядка;
- подготовка к безопасной высадке.

## 9. Что остаётся контентом

Scenario/config задаёт:

- длительность preDeparture;
- длительность originStop/boarding;
- departure/arrival schedule;
- route stops;
- service windows;
- распределение service-class traits пассажиров;
- конкретные параметры response/quality assessment.

Engine предоставляет только общие механизмы времени, selectors, actions, traits/events и assessment hooks.
