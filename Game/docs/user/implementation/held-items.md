# Переносимые предметы текущего demo

**Версия документа:** 0.2.0  
**Статус:** Draft / concrete demo implementation  
**Дата редакции:** 2026-09-27

## 1. Общая модель

Для текущего вертикального среза проводник держит не более одного предмета:

```ts
heldItemId?: ItemId;
```

Полноценный многослотовый inventory не требуется.

Item не является Entity: в текущей release-модели Entity — только player/passenger.

## 2. Переносимые предметы

Текущий release предусматривает:

1. журнал приёмки;
2. огнетушитель;
3. простую единицу еды;
4. простой напиток.

Билет и паспорт пассажира показываются через interaction/modal и не обязаны становиться физическими held-items мира.

## 3. Журнал приёмки

### Начальное состояние

В начале смены журнал находится на исходном перроне в настроенном Level anchor (`platform.acceptance-desk` или эквивалент).

Игрок должен забрать его перед осмотром вагона.

### Действия

- открыть;
- закрыть;
- изменить checklist;
- изменить замечание;
- вернуть журнал в исходный anchor перед отправлением.

### Ограничения

Journal state не заполняется автоматически из фактического состояния мира.

Scenario проверяет документ как pre-departure gate: все checklist-поля должны быть заполнены, игрок должен отметить вагон как принятый и вернуть журнал на исходную точку. Некритическое санитарное замечание не блокирует продолжение; технический `problem` по связи, огнетушителю, климату или аварийному тормозу считается критическим и завершает попытку. Assessment в момент сдачи сравнивает критические отметки с фактическим состоянием оборудования.

## 4. Огнетушитель

Огнетушитель является одним world object/item, который меняет ownership/spatial state:

```text
mounted
  ↓ take
held
  ↓ prepare/remove pin
held + prepared
  ↓ use on fire
held + used/partially used
```

Минимальные действия:

- осмотреть;
- взять;
- вернуть;
- подготовить;
- использовать.

## 5. Еда и напиток

В текущем release обслуживание максимально простое.

В вагоне существует service point/storage с простой модалкой:

```text
[ Взять еду ]
[ Взять напиток ]
```

Action создаёт/выдаёт соответствующий простой Item и помещает его в единственный held slot игрока.

Пример:

```text
heldItem = food
```

или:

```text
heldItem = drink
```

Возле пассажира сервер может предложить:

```text
give-food
give-drink
```

Передача предмета создаёт domain event (`ItemGiven` или эквивалент), который может завершить waiting action пассажира.

## 6. Что не моделируется в текущем release

Пока не нужны:

- подносы;
- типы блюд;
- остатки запасов;
- посуда;
- мусор/упаковка;
- сбор использованной посуды;
- возврат предметов после еды;
- отдельная уборка после питания.

После передачи еда/напиток может быть потреблён/удалён обычным passenger action без появления мусора.

Для временной реализации допускаются простые UI-иконки/подписи без отдельных художественных ассетов еды и напитка.

## 7. Held state и действия

Наличие предмета в руке влияет на доступные actions.

Например:

```text
empty hand
  -> take journal / take extinguisher / take food / take drink

held drink + near waiting passenger
  -> give-drink

held extinguisher + fire
  -> inspect / prepare / use
```

Все preconditions проверяются Game Server.

## 8. Client presentation

Client получает только public state:

```text
player held item changed -> drink
```

и сам выбирает представление:

- слой в руке;
- иконка held slot;
- placeholder icon;
- оба варианта одновременно.

Конкретный art asset не влияет на simulation semantics.
