# Environment state текущего demo

**Версия документа:** 0.1.0  
**Статус:** Draft / concrete demo implementation  
**Дата редакции:** 2026-09-27

## 1. Назначение

Документ описывает конкретные spatial/environment решения текущего demo, которые не должны превращаться в общие правила движка.

Основные темы:

- санитарные overlays;
- исходный перрон;
- подключаемый перрон на остановках;
- поведение внешнего фона во время движения;
- связь этих состояний со Scenario.

## 2. Санитарное состояние

Санитарная обстановка отображается накладываемыми visual tiles поверх базовой карты.

Примеры:

```text
trash-small-01
spill-01
stain-seat-01
```

Server хранит runtime contamination component и публичный `visualId`. Client сопоставляет ID локальному asset.

Для baseline:

- загрязнения создаются стартовым состоянием/Scenario;
- отдельной симуляции загрязнения нет;
- уборка не реализуется;
- загрязнение остаётся статичным на протяжении run;
- игрок только замечает его и корректно/некорректно отражает санитарное состояние в журнале.

Позднее `clean` может стать обычным Action, удаляющим contamination component без изменения модели данных.

## 3. Перрон: выбранный вариант

Для baseline выбран **вариант v2: перрон как временно подключаемый spatial region**.

Он является частью Level, но участвует в активной topology только в нужные интервалы Scenario.

```text
[ platform region ]
        || door connection
[ carriage-main ]
```

Это позволяет физически показывать пассажиров снаружи вагона, не моделируя поезд как объект, движущийся по большой внешней карте.

## 4. Исходный перрон и preDeparture

В начале попытки активны:

```text
carriage-main
platform-origin
```

Игрок начинает в области исходного перрона/вагона согласно Level preset.

Журнал приёмки лежит в `platform.acceptance-desk` или другом настроенном anchor.

Игрок:

1. забирает журнал;
2. входит в вагон;
3. проводит приёмку;
4. заполняет журнал;
5. возвращает журнал в исходную точку до отправления.

Пассажирского потока во время `preDeparture` нет.

## 5. Остановка

На обычной остановке Scenario активирует platform region и соединение через дверь.

Client визуально показывает дополнительную область рядом с вагоном.

Passenger flow происходит физически через этот region:

```text
spawn/available on platform
        ↓
walk through door
        ↓
carriage
```

и наоборот для высадки.

## 6. Движение поезда

Baseline не требует:

- анимации отправления;
- анимации прибытия;
- движущегося внешнего мира;
- полноценной внешней локации вдоль маршрута.

При начале travel interval:

```text
door/platform connections disabled
platform region inactive/hidden
```

Внешний фон может быть:

- нейтральным;
- пустым;
- стилизованным статичным travel background.

Эта деталь является presentation policy и не влияет на simulation.

## 7. Повторное использование перрона

Для первой версии один `platform-standard` может повторно использоваться на нескольких остановках.

Перед новой остановкой Scenario создаёт/размещает новый passenger flow, а предыдущий transient stop state очищается.

Разные station assets/geometry добавляются только если это станет заметной частью gameplay.

## 8. Граница Level и Scenario

Level содержит:

```text
геометрию carriage/platform regions
anchors
дверные connections
asset references
```

Scenario содержит:

```text
когда region активен
сколько длится остановка
сколько пассажиров входит/выходит
какие параметры получают пассажиры
```

Client только отображает активную публичную геометрию и entities.
