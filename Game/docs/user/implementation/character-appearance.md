# Персонажи и визуальная сборка

**Версия документа:** 0.1.0  
**Статус:** Draft  
**Дата редакции:** 2026-09-27

## 1. Общая модель

Персонаж визуально собирается из базового манекена и накладываемых клиентских ассетов.

Минимальная композиция:

```text
body/mannequin
+ clothing layers
+ optional accessory layers
+ optional held-item layer
```

Формат самих изображений и точная система якорей пока не фиксируются.

## 2. Ответственность сервера

Game Server не хранит изображения и не занимается их композицией.

Он может передавать публичное описание внешности через стабильные IDs, например:

```ts
interface CharacterAppearanceView {
  bodyId: string;
  clothingIds: string[];
  accessoryIds?: string[];
  heldItemVisualId?: string;
}
```

Конкретная schema может измениться после утверждения art pipeline.

## 3. Ответственность клиента

Client:

- разрешает ID через локальный asset registry;
- накладывает слои в правильном порядке;
- выбирает нужную ориентацию/анимацию;
- визуализирует удерживаемый предмет;
- может иметь fallback для отсутствующего ассета.

Сервер не должен отправлять URL или filesystem path как часть game semantics.

## 4. Манекен и одежда

Для первой версии достаточно малого набора совместимых базовых тел и одежды.

Требование к art pipeline:

- одинаковая система координат/якорей для совместимых слоёв;
- предсказуемый порядок наложения;
- возможность заменить один слой без перерисовки персонажа целиком;
- поддержка как минимум idle/walk представления, если это требуется текущей анимацией.

## 5. Предметы в руках

На текущем demo переносимыми являются:

- журнал приёмки;
- огнетушитель.

Для них желательно иметь либо отдельные held-варианты, либо общий способ отображения предмета в руке персонажа.

Точный вариант — полноценный слой в руках или условный визуальный слот/иконка — может быть выбран после первого art spike.

## 6. Что не относится к server domain

Не являются simulation state сами по себе:

- цвет пикселей одежды;
- конкретный размер texture;
- локальный font;
- порядок atlas frames;
- способ tween/animation на клиенте.

Simulation хранит только значения, которые имеют игровой смысл или нужны для однозначного публичного представления.
