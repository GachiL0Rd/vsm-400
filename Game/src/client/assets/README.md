# Клиентские ассеты карты и персонажей

Персонаж проводника — PNG в `assets/characters/provodnik/`. Клиент импортирует их через Vite `?url` и кладёт в кэш Phaser в `preload`.

## Карта `train2-long`

`map/train2-long.map.json` — конечный Tiled JSON. Его пишет `npm run map:build` из `assets/map/train2-long.tmx` (один длинный вагон). `npm run map:check` падает, если закоммиченный JSON разошёлся с генератором. Карта конечная, 96×16 тайлов: чанки склеены в полуинтервале x −16…80, y 0…16. Свойства карты `originX` = −16 и `originY` = 0.

Клиент не хранит свою сетку. Публичная клетка `(x, y)` рисуется в тайле `(x, y)`:

```text
центр = ((x − originX) · 64 + 32, (y − originY) · 64 + 32)
```

Если у региона `visualId` начинается с `map.train2-long`, сцена грузит этот JSON (`this.load.tilemapTiledJSON`) и три PNG тайлсетов из `assets/map/` тем же `?url`. Имена тайлсетов в JSON: `VSM long car interior`, `VSM long car exterior`, `VSM streamlined nose`. Поле `image` внутри JSON — имя файла рядом с TMX; загрузчик Phaser его не подхватывает. Текстуры связываются через `addTilesetImage`. Слои-тайлы создаются по порядку под актёрами. Объектные слои Tiled клиент не рисует: объекты приходят из публичного состояния и ставятся на свою клетку.

Уровень без этого префикса (например `vsm-baseline-01`) берёт origin как минимум `x`/`y` публичных клеток и рисует каждую клетку квадратом 64×64.

PNG тайлсетов в JSON указаны полем `image` и лежат рядом с TMX, не внутри клиентского JSON.
