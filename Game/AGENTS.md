# Правила работы с проектом vsm-moscow

## Контекст и границы

- Этот каталог `Game/` — весь отслеживаемый Git-проект. Все изменения, предназначенные для репозитория, вносите только сюда.
- Команда выбрала браузерную игру на Phaser 4. Официальное ТЗ хакатона ещё не получено; прежние идеи об игре и изометрии не считать утверждёнными требованиями. Не реализуйте игровые механики по предположениям.
- Разрешённый стек приложения и сборки: **Phaser 4, TypeScript, Vite**. Не добавляйте другие фреймворки, движки, библиотеки интерфейса или сборки без явного решения команды.
- `README.md` не создавайте: инструкции и история проекта находятся в `AGENTS.md` и `PROGRESS.md`.

## Текущее устройство

- `index.html` — контейнер игрового canvas.
- `src/main.ts` — точка входа Phaser и временная стартовая сцена. Надпись `Phaser ready` служит проверкой запуска, это не игровой контент.
- `vite.config.ts` — конфигурация сборки с относительными путями к ассетам.
- `package.json` и `package-lock.json` — зафиксированные версии зависимостей и npm-скрипты.
- `.gitignore` — исключает `node_modules/`, `dist/` и локальные файлы Node-инструментов.
- `PROGRESS.md` — журнал выполненной работы, решений и открытых вопросов.

## Как начать работу

Нужны Node.js `^20.19.0` или `>=22.12.0` и npm. Выполняйте команды из каталога `Game/`:

```sh
npm ci
npm run dev
```

Сборка и отдельная проверка типов:

```sh
npm run build
npm run typecheck
```

`npm run build` уже включает проверку типов. Результат сборки попадает в `dist/` и не коммитится.

## Работа над задачами

1. Перед изменением проверьте `git status`, файлы в `src/` и последние записи `PROGRESS.md`. Не удаляйте чужие незавершённые изменения.
2. Делайте минимальное изменение в рамках задачи. Для контента и механик опирайтесь на полученное ТЗ или явное решение команды; спорные предположения записывайте в открытые вопросы.
3. После изменения выполните `npm run build`. Для визуальных изменений дополнительно проверьте страницу через `npm run dev` в браузере.
4. Добавьте запись в `PROGRESS.md`: дата, автор/агент, что сделано, как проверено, что остаётся или блокирует продолжение. Сохраняйте прежние записи.
5. Перед коммитом убедитесь, что в него входят только файлы внутри `Game/`; не коммитьте `node_modules/` и `dist/`.

Обновляйте документацию и зависимости только вместе с соответствующим изменением проекта. Используйте зафиксированную мажорную версию Phaser 4; при обновлении версии проверяйте сборку и запуск сцены.
