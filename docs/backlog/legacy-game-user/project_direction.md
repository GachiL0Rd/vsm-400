# Направление развития и границы модулей

## Текущее состояние

Сейчас существует только `Game/` — браузерная игра на Phaser. В будущем рядом
могут появиться:

- клиент-оболочка, в которую встраивается игра;
- сервер авторизации, профиля, результатов, статистики и достижений;
- межмодульная сборка и интеграционная проверка.

Способ встраивания, сетевой протокол и стек будущих модулей пока не выбраны.
Создавать их заготовки до появления требований не нужно.

## Переносимая игровая логика

Доменная часть игры должна проверяться без браузера и движка. К ней относятся:

- состояние смены и переходы между этапами;
- игровое время и правила событий;
- состояния объектов и пассажиров;
- проверка действий игрока;
- потенциальная оценка и фактические последствия;
- результат рейса и достижения.

Эта логика не импортирует Phaser, DOM или Vite. Phaser-слой преобразует ввод и
события движка в доменные команды и отображает получившееся состояние.

Время и случайность, влияющие на результат, должны подаваться через явные
контролируемые границы. Это позволяет воспроизводить сценарии обычными
TypeScript-тестами вместо проверки каждой ошибки через полный E2E-запуск.

## Будущая интеграция

Клиент и сервер не должны зависеть от внутреннего состояния Phaser. На границе
передаётся компактный версионируемый результат: идентификатор сценария,
показатели, ключевые события, ошибки, достижения и итог рейса.

Пока второго потребителя нет, доменная логика остаётся внутри `Game/src` с
правильным направлением импортов. Выделение общего package выполняется только
после появления реального клиента или сервера, которому нужен тот же код или
контракт.

## Будущий CI

Каждый модуль обязан иметь собственную независимую проверку. Корневой CI позже
соберёт их в последовательность:

```text
Game checks ─────┐
Client checks ───┼─> межмодульная сборка и интеграционная проверка
Server checks ───┘
```

До появления второго модуля реализуется только проверка `Game/`.
