# Что осталось реализовать по `vsm-docs-iteration-07`

**Состояние на 2026-09-27.** Проверены текущая ветка `feature/vsm-docs-iteration-07-wip`, код `Game/` и требования в [индексе документации](../../Game/docs/vsm-docs-iteration-07/README.md). Этот список описывает недостающую **работающую связку**, а не только отсутствие отдельных файлов. Более ранняя таблица расхождений находится в [iteration-07-gap-analysis.md](iteration-07-gap-analysis.md).

## Что уже есть и почему этого пока недостаточно

В `Game/src/simulation/` реализованы и отдельно протестированы время в целых микросекундах, очередь событий, планировщик, RNG, grid, движение по edges, поля, EntityStore, выбор NPC action и ItemStore. `action-runtime.ts` дополнительно связывает ожидание еды/напитка с выдачей предмета, успехом, таймаутом и прерыванием. Очередь поддерживает атомарную замену события с generation token.

Эти модули пока не образуют игровую попытку. Запускаемый [demo-server.ts](../../Game/dev/demo-server.ts) использует собственное состояние с четырьмя зонами, `Date.now()` и фазами `boarding/ride/finished`. Клиент читает старый [protocol.ts](../../Game/src/client/protocol.ts). Поэтому успешные unit-тесты примитивов не подтверждают готовность вертикального среза.

## 1. Единый runtime попытки — обязательно

- [ ] **Level.** Добавить versioned, JSON-compatible `LevelDefinition`, проверку данных и один baseline preset: `carriage-main`, `platform-origin`, `platform-standard`, cells/edges, связи регионов, anchors, места объектов, неисправностей и санитарных overlays. На стоянке перрон должен подключаться к навигации, при отправлении отключаться. Сейчас модуля Level и его загрузки нет. Основание: [level.md](../../Game/docs/vsm-docs-iteration-07/simulation/level.md), [grid-world.md](../../Game/docs/vsm-docs-iteration-07/simulation/grid-world.md).
- [ ] **Scenario и конкретный рейс.** Создать versioned Scenario, совместимый с Level: отдельные `preDeparture` и `originStop`, последовательность travel/route stops с `dwell`, посадку и высадку, 2–3 пассажиров, service windows, incident, terminal rules и штатный финиш. Журнал должен вернуться в исходный anchor до отправления; критическая неисправность может завершить попытку досрочно. Сейчас Scenario runtime отсутствует. Основание: [scenario.md](../../Game/docs/vsm-docs-iteration-07/simulation/scenario.md), [trip-service-plan.md](../../Game/docs/vsm-docs-iteration-07/implementation/trip-service-plan.md), [baseline](../../Game/docs/vsm-docs-iteration-07/vsm_baseline_vertical_slice.md).
- [ ] **GameAttempt/worker.** Собрать Level, Scenario, clock, одну event queue, RNG streams, entities, spatial world, fields, items, actions, NPC decisions и assessment в одну authoritative попытку. Ввод применять с серверным `SimTimeUs` и стабильным порядком между тиками; движение, вместимость cells, достижимость и дистанцию взаимодействия проверять на сервере. Устранить риск расхождения позиций EntityStore и SpatialWorld. Основание: [event-loop.md](../../Game/docs/vsm-docs-iteration-07/simulation/event-loop.md), [determinism.md](../../Game/docs/vsm-docs-iteration-07/simulation/determinism.md), [client-server.md](../../Game/docs/vsm-docs-iteration-07/architecture/client-server.md).
- [ ] **Полный цикл действий.** Подключить каталог content definitions и handler registry к попытке: `canStart`, instant/running/waiting actions, scheduling, completion, interrupt, outcome и обработку событий. Текущий `action-runtime.ts` покрывает только запрос еды/напитка и не управляет общим циклом NPC и игрока. Trait candidates, hard restrictions и stable softmax должны реально выбирать действия пассажиров. Основание: [actions.md](../../Game/docs/vsm-docs-iteration-07/simulation/actions.md), [traits.md](../../Game/docs/vsm-docs-iteration-07/simulation/traits.md), [selectors.md](../../Game/docs/vsm-docs-iteration-07/simulation/selectors.md).
- [ ] **Данные пассажиров и услуг.** Ввести валидируемый baseline content для traits, действий, документов и классов `basic/comfort/business`; каждый пассажир имеет ровно один class trait. Запрос вне положенного класса разрешён как действие, а его оценка зависит от entitlement и качества обслуживания. Основание: [service-levels.md](../../Game/docs/vsm-docs-iteration-07/implementation/service-levels.md), [traits.md](../../Game/docs/vsm-docs-iteration-07/simulation/traits.md).
- [ ] **Мир и предметы.** Подключить ItemStore к реальным взаимодействиям: взять/заполнить/вернуть журнал; осмотреть, подготовить и применить огнетушитель; взять еду/напиток в service point и передать пассажиру при одном held slot. Реализовать mutable state и server actions для климата, стоп-крана, связи с машинистом, дверей и санитарных overlays. Панель показывает наблюдаемое, а не скрытое фактическое состояние. Основание: [interactables.md](../../Game/docs/vsm-docs-iteration-07/implementation/interactables.md), [held-items.md](../../Game/docs/vsm-docs-iteration-07/implementation/held-items.md), [environment-state.md](../../Game/docs/vsm-docs-iteration-07/implementation/environment-state.md).
- [ ] **Нештатная ситуация.** Связать источник пожара/давления с periodic field updates, доступными признаками, NPC реакциями, действиями игрока и последствиями. Для baseline достаточно простой модели, но изменение поля и исход должны происходить в authoritative runtime. Основание: [grid-world.md](../../Game/docs/vsm-docs-iteration-07/simulation/grid-world.md), [baseline](../../Game/docs/vsm-docs-iteration-07/vsm_baseline_vertical_slice.md).

## 2. Граница сервера, режимы и результат — обязательно

- [ ] **Platform gateway.** Ввести `SessionKey → resolveSession`, локальное разрешение `gameLevelId` в preset, `ResumeToken`, сервисную аутентификацию, mock adapter для локального запуска и идемпотентный `finishSession`. Формировать `FinishedGameResult` и `FinishReceipt`; replay не отправляет новый официальный результат. Текущий WebSocket hello принимает только необязательный `sessionId`. Основание: [platform-contract.md](../../Game/docs/vsm-docs-iteration-07/architecture/platform-contract.md).
- [ ] **Lifecycle сессии и WebSocket.** Отделить GameAttempt от соединения: создание/подключение, detach/reconnect, resume, политика паузы/времени без клиента, сериализация команд одного attempt, revision/resync и обработка медленного клиента. Сохранить одну встраиваемую WebSocket границу. Основание: [client-server.md](../../Game/docs/vsm-docs-iteration-07/architecture/client-server.md).
- [ ] **Public projection и новый wire contract.** Строить сообщения только из наблюдаемого состояния и разрешённых контекстных действий с runtime handles; не отправлять latent traits, RNG, скрытые неисправности и входы оценщика. Передавать видимые cells/regions, объекты, движение, модальные данные и presentation events; версионировать протокол и проверять команды на сервере. Старый zone-based DTO этим требованиям не соответствует. Основание: [client-server.md](../../Game/docs/vsm-docs-iteration-07/architecture/client-server.md), [modal-content.md](../../Game/docs/vsm-docs-iteration-07/implementation/modal-content.md).
- [ ] **Режимы и replay.** Одна simulation для `live`, `guided`, `replay`; server-side `InputPolicy` запрещает gameplay commands в replay. Записывать canonical source: версии simulation/content, root seed и authoritative user inputs с `SimTimeUs`/порядком. Сделать детерминированное forward replay, playback controls, seek через повтор от начала и разрешённую inspection/reveal policy. Checkpoints могут ускорять seek, но не являются обязательным источником истины. Основание: [session-modes.md](../../Game/docs/vsm-docs-iteration-07/architecture/session-modes.md), [replay.md](../../Game/docs/vsm-docs-iteration-07/architecture/replay.md).
- [ ] **Оценка и завершение.** Считать `safety`, `customerSatisfaction`, achievements и отдельный `terminalReason` из событий попытки; выдавать run achievements один раз. Guided hints должны быть presentation events, не менять simulation и не раскрывать hidden state без policy. Разделить досрочное завершение и оценку безопасности. Основание: [feedback.md](../../Game/docs/vsm-docs-iteration-07/simulation/feedback.md), [scenario.md](../../Game/docs/vsm-docs-iteration-07/simulation/scenario.md).

## 4. Проверка готовности

- [ ] Пройти в браузере короткую смену: перрон → журнал и приёмка → отдельная посадка → поездка/остановка → пассажиры и документы → техническая или пожарная ситуация → штатный или досрочный итог.
- [ ] Проверить на сервере отклонение недоступного действия, слишком далёкого взаимодействия, входа в отключённый перрон и gameplay command в replay; отсутствие hidden state в обычной проекции.
- [ ] Повторить сохранённый ввод с тем же seed/versions и получить тот же итог, NPC decisions и ключевые события; проверить reconnect/resync и однократный `finishSession`.
- [ ] Запустить `npm run verify` из `Game/` после интеграции и провести ручную браузерную проверку. Текущая проверка примитивов не заменяет эти сквозные сценарии.

**Критерий закрытия списка:** весь путь из [baseline vertical slice](../../Game/docs/vsm-docs-iteration-07/vsm_baseline_vertical_slice.md) работает на новом authoritative GameAttempt через public projection, даёт воспроизводимый replay source и официальный результат. Несколько типов вагонов, полноценный поезд, многослотовый inventory, точная физика пожара/давления, runtime LLM, reversible event log и сохранённые checkpoints в baseline не требуются.
