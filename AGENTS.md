# Роутинг работы в репозитории VSM Moscow

## Роль этого файла

Корневой `AGENTS.md` определяет только выбор модуля, межмодульные границы и
общий Git-процесс. Требования, framework API, зависимости, команды и проверки
принадлежат ближайшему `AGENTS.md` модуля.

## Перед началом работы

1. Прочитайте `README.md`.
2. Определите затронутый модуль и прочитайте его ближайший `AGENTS.md` до
   изменения файлов.
3. Проверьте `git status`; не удаляйте и не включайте в свою задачу чужие
   незавершённые изменения.
4. Если задача меняет границу между модулями, прочитайте требования и контракты
   всех затронутых модулей до реализации.

## Модули

| Каталог | Назначение | Локальные инструкции |
| --- | --- | --- |
| `Game/` | Browser Game Client и Game Server | `Game/AGENTS.md` |
| `Backend/` | API тренажёра: NestJS 11, Fastify, Prisma, PostgreSQL | `Backend/AGENTS.md` |
| `Server/` | Backend тестового личного кабинета: Hono, `node:sqlite`, TS без сборки | `Server/AGENTS.md` |
| `Client/` | Статический личный кабинет (HTML/CSS/JS), точка входа в игру | `Client/AGENTS.md` |

Когда появится новый модуль, добавьте его в эту таблицу и дайте ему собственные
инструкции и независимую команду проверки.

## Межмодульные границы

- Внешний Platform Server не входит в этот репозиторий. Он владеет
  аутентификацией, попытками и постоянными результатами; Game не должен
  создавать его заготовки без отдельной задачи.
- Межмодульное взаимодействие проходит только через документированный контракт.
  Не импортируйте внутренний код одного модуля в другой и не переносите файлы
  между модулями без явной необходимости.
- Изменение публичного контракта, состава модулей, инфраструктуры или
  направлений зависимостей требует отдельной задачи и согласованного обновления
  документации затронутых модулей.

## Ветки и интеграция

`main` — основная ветка разработки и содержит запускаемое проверенное состояние.
Работа ведётся в короткоживущих `feature/*`, `fix/*`, `docs/*` и `chore/*`
ветках от `main` с последующим возвратом в `main`. Ветка `release` хранит
отобранные стабильные снимки для выпуска; новые изменения переносятся в неё из
проверенного `main`. Ветка `dev` не используется для новой работы. Полный
процесс, release-gate и требования к передаче работы описаны в
[`docs/agent/workflow.md`](docs/agent/workflow.md). Не коммитьте секреты и
локальное состояние инструментов.
